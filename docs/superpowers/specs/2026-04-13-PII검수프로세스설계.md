# PII 검수 프로세스 설계

**작성일:** 2026-04-13  
**스택:** FastAPI + SQLAlchemy + SQLite · React 18 + Vite + Tailwind CSS

## 전체 흐름

```
로그 업로드 → 파싱 → DB 저장 → 로그인 → 검수 → 내보내기
```

## Phase 1 — 로그 업로드 & 파싱

### 로그 블록 구조

로그 파일은 `🔍 LLMExtractService 시작` 줄을 기준으로 블록 단위로 분리된다.

```
2026-04-10 21:19:56,769 [INFO] 🔍 LLMExtractService 시작 - MODE: ftp, path: /tmp/pdf-260410-xxx/texts_chunked.json
2026-04-10 21:19:56,843 [INFO] [Source] source_filename=
{source_filename}

2026-04-10 21:19:56,907 [INFO] [preprocess] text_len={n}, chunks={n}
2026-04-10 21:19:56,907 [INFO] [run_pipeline] doc_text=
{doc_text (여러 줄 가능)}

...

2026-04-10 21:19:59,623 [INFO] [inference] [1/1] pii_dict=
{pii_dict Python dict literal (여러 줄 가능)}
```

### 추출 필드

| 필드 | 소스 | 비고 |
|------|------|------|
| `path` | 블록 첫 줄 `path: ...` | DB UNIQUE 키 (전체 경로 그대로) |
| `service_started_at` | 블록 첫 줄 타임스탬프 | `2026-04-10 21:19:56` |
| `source_filename` | `[Source] source_filename=` 다음 줄 | strip 처리 |
| `source` | `path` 파일명 패턴으로 판별 | `text` \| `ocr` (하단 참조) |
| `text_len` | `[preprocess] text_len=` | 정수 |
| `doc_text` | `[run_pipeline] doc_text=` 이후 줄들 | 다음 타임스탬프 줄까지 수집, strip |
| `pii_dict` | `[inference] pii_dict=` 이후 줄들 | 다음 타임스탬프 줄까지 수집 → `ast.literal_eval` |

### `source` 판별 규칙

`path`의 파일명으로 구분한다.

| 파일명 패턴 | `source` 값 |
|------------|------------|
| `*texts_chunked*.json` | `text` |
| `*ocr_chunked*.json` | `ocr` |
| 그 외 | `text` (기본값) |

### 멀티라인 필드 수집 규칙

`doc_text`와 `pii_dict`는 여러 줄에 걸쳐 기록될 수 있다.  
**수집 종료 조건:** `YYYY-MM-DD HH:MM:SS` 형식의 타임스탬프로 시작하는 새 줄이 나타나면 종료.

### 스킵 조건

블록 내에 `pii_dict=` 줄이 없으면 해당 블록은 **DB 저장에서 제외**한다.

```
# 스킵 예시 (pii_dict 없음)
🔍 LLMExtractService 시작 - path: /tmp/docx-.../texts_chunked.json
[Source] source_filename= only_ocr.docx
→ pii_dict 없음 → SKIP
```

### 재업로드 중복 처리

- DB에서 `MAX(service_started_at)` 조회
- 업로드된 로그에서 해당 타임스탬프 **이후** 레코드만 INSERT
- 이전 데이터는 건드리지 않음

## Phase 2 — DB 스키마

### `users`

| 컬럼 | 타입 | 비고 |
|------|------|------|
| `id` | INTEGER PK | auto increment |
| `username` | VARCHAR UNIQUE | |
| `password_hash` | VARCHAR | bcrypt |
| `role` | VARCHAR | `admin` \| `reviewer` |

### `records`

| 컬럼 | 타입 | 비고 |
|------|------|------|
| `id` | VARCHAR PK | UUID |
| `path` | VARCHAR UNIQUE | `/tmp/.../xxx_chunked.json` 전체 경로 |
| `source_filename` | VARCHAR | 원본 문서 파일명 |
| `source` | VARCHAR | `text` \| `ocr` |
| `service_started_at` | DATETIME | 블록 시작 타임스탬프 |
| `doc_text` | TEXT | |
| `pii_dict` | JSON | LLM이 추출한 원본 pii_dict |
| `status` | VARCHAR | `pending` \| `reviewing` \| `reviewed` |
| `reviewed_pii_dict` | JSON | 검수 후 수정된 pii_dict |
| `complexity` | VARCHAR NOT NULL | `low` \| `medium` \| `high` — 검수 저장 시 필수 선택 |
| `reviewed_by` | INTEGER FK → users | |
| `reviewed_at` | DATETIME | |

**상태값 표시명:**

| DB 값 | 화면 표시 |
|-------|----------|
| `pending` | 검수전 |
| `reviewing` | 검수중 |
| `reviewed` | 검수완료 |

**complexity 선택 방법:**  
검수 화면에서 저장 전에 반드시 선택해야 한다. 미선택 상태에서 저장 시 경고를 표시하고 저장을 막는다.

### `log_uploads`

| 컬럼 | 타입 | 비고 |
|------|------|------|
| `id` | INTEGER PK | |
| `original_filename` | VARCHAR | 업로드된 로그 파일명 |
| `records_inserted` | INTEGER | 이번 업로드에서 추가된 레코드 수 |
| `last_service_started_at` | DATETIME | 이번 업로드의 마지막 타임스탬프 |
| `uploaded_by` | INTEGER FK → users | |
| `uploaded_at` | DATETIME | |

## Phase 3 — API

```
POST /auth/login              # JWT 발급
GET  /auth/me                 # 현재 사용자 정보

GET  /records                 # 레코드 목록 (페이지네이션)
GET  /records/{id}            # 레코드 상세
PATCH /records/{id}/status    # 상태 변경 (admin: reviewed→reviewing 되돌리기)
PUT  /records/{id}/review     # 검수 저장 (reviewed_pii_dict + complexity + reviewed 전환)
GET  /records/export          # reviewed 레코드 JSON 다운로드

POST /logs/upload             # 로그 파일 업로드 & 파싱
GET  /logs/uploads            # 업로드 이력
```

## Phase 4 — 검수 흐름

### 상태 전환

```
pending (검수전)
  └→ reviewing (검수중)    ← 레코드 열면 자동 전환
       └→ reviewed (검수완료)  ← 저장 버튼 클릭 시
            └→ reviewing (검수중)  ← admin만 되돌리기 가능
```

### 검수 UI (ReviewPage)

- **좌측 패널:** 원문 텍스트 (`doc_text`) — Ctrl+F 검색 지원
- **우측 패널:** PII 검수 (`PiiEditor`) — 카테고리별 추가/삭제/수정/드래그
- **complexity 선택:** `low / medium / high` 중 하나를 반드시 선택해야 저장 가능 — 미선택 시 저장 버튼 비활성화
- **저장:** 저장 버튼 또는 `Ctrl+S` → `PUT /records/{id}/review` 호출 → 즉시 `reviewed` 전환
- **내비게이션:** 이전/다음 레코드 이동

### PII 카테고리 (9개 고정)

```
NAME  ADDRESS  POSTAL  RESIDENT  CONTACT  EMAIL  BIRTHDATE  GENDER  AGE
```

## Phase 5 — 내보내기

`GET /records/export` 호출 → `reviewed` 상태 레코드만 JSON 반환

```json
[
  {
    "id": "uuid",
    "path": "/tmp/pdf-260410-xxx/texts_chunked.json",
    "source_filename": "example.pdf",
    "source": "text",
    "doc_text": "...",
    "pii_dict": { "NAME": ["김철수"], "ADDRESS": [], "..." : [] },
    "complexity": "medium",
    "reviewed_by": "reviewer1",
    "reviewed_at": "2026-04-10T21:20:00Z"
  }
]
```
